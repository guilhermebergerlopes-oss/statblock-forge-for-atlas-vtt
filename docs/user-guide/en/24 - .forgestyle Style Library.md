# .forgestyle Style Library

The **Style library** lets users share custom themes and outer frames between Statblock Forge installations. A `.forgestyle` file is a validated JSON data package; it is not a CSS file, snippet, or Obsidian theme.

## Import and export locations

### Settings → Style library

In plugin settings:

- **Import .forgestyle** opens a file picker to import a package.
- **Export style library** exports all reusable themes and borders registered in Forge settings as one package. The button is disabled while the library is empty.

### Template → Appearance

In the Template editor's **Appearance** tab:

- **Import .forgestyle** imports a package into the library.
- **Export style library** appears when the library contains styles.
- **Export this theme** exports only the selected/current theme.
- **Export this border** exports only the selected outer frame.

Exported packages use the `.forgestyle` extension. The importer also accepts valid JSON that conforms to the package schema.

## What can be shared

A package can contain:

1. **Theme:** a custom theme with a name, ID, and eight-color palette.
2. **Border:** an outer frame with style, color, thickness, radius, and optional inner-line settings.
3. **Collection:** a collection containing at least one theme and one border.

A library export gathers reusable themes and borders saved in plugin settings. An individual export includes only the selected item.

The library does not export:

- complete Templates, Fields, Samples, or Canvas layout;
- statblock Values;
- Vault images or files;
- individual appearance overrides for every block;
- Token art and its frame;
- image-framing settings;
- CSS, snippets, or executable code.

## Package structure

The current format uses `format: "statblock-forge-style"` and `version: 1`. Example collection:

```json
{
  "format": "statblock-forge-style",
  "version": 1,
  "kind": "collection",
  "name": "Ashen Copper Styles",
  "themes": [
    {
      "id": "ashen-copper-01",
      "name": "Ashen Copper",
      "palette": {
        "background": "#171412",
        "surface": "#24201c",
        "raised": "#332a22",
        "border": "#76583e",
        "accent": "#bd7b42",
        "accentStrong": "#edaa63",
        "text": "#f0e6d8",
        "muted": "#b8a28a"
      }
    }
  ],
  "borders": [
    {
      "id": "etched-double-01",
      "name": "Etched Double",
      "style": "double",
      "color": "#bd7b42",
      "width": 4,
      "radius": 8,
      "inner": true,
      "innerColor": "#f0e6d8",
      "innerWidth": 1,
      "innerGap": 3
    }
  ]
}
```

This demonstrates the JSON structure; the palette and border values are illustrative.

### Theme fields

- `id`: stable identifier, 2–64 characters, using lowercase letters, numbers, `_`, or `-`, starting with a letter or number.
- `name`: plain text up to 64 characters.
- `palette`: must contain the eight colors `background`, `surface`, `raised`, `border`, `accent`, `accentStrong`, `text`, and `muted`.
- Each color must be six-digit hexadecimal, such as `#bd7b42`.

### Border fields

- `id` and `name`: style identifier and name.
- `style`: `none`, `solid`, `double`, `dashed`, `dotted`, `groove`, or `ridge`.
- `color` and `innerColor`: `#RRGGBB` hexadecimal colors.
- `width`: 0–16 px.
- `radius`: 0–48 px.
- `inner`: `true` or `false`, enables or disables the inner line.
- `innerWidth`: 0–8 px.
- `innerGap`: 0–24 px.

## Limits and validation

- Maximum file size: **512 KB**.
- Maximum total: **100 styles**, counting themes and borders together.
- `kind: "theme"` requires at least one theme and accepts no borders.
- `kind: "border"` requires at least one border and accepts no themes.
- `kind: "collection"` requires at least one theme and one border.
- Duplicate IDs within the same list are rejected.
- Extra or unknown properties are rejected; only the documented keys are accepted.

> [!warning] The package is data-only
> Forge does not execute imported content. The importer rejects CSS, HTML, SVG, scripts, URLs, event handlers, expressions, and arbitrary properties. A `.forgestyle` file is not a way to install snippets or execute code in the Vault.

## Resolve conflicts during import

After selecting the file, Forge validates it and opens **Import style package**. Every theme and border has a row with a preview, name, and import action.

| Action | When it appears | Result |
|---|---|---|
| **Add to library** | No conflict exists | Adds the style to the library. |
| **Keep both (import as copy)** | A conflict exists | Keeps the current style and imports a copy with a unique name/ID. This is the default choice. |
| **Replace matching style** | A conflict exists | Replaces the matching entry while retaining the local ID of the replaced entry. |
| **Skip this style** | Always | Does not import that entry. |

A conflict is detected when IDs match or names match case-insensitively. For copies, Forge suggests ` (Imported)` and generates unique IDs when needed. The name can be edited before confirming; the limit is 64 characters.

Decisions can be mixed: for example, copy a theme, replace a border, and skip another theme. If no styles are selected for import, the library remains unchanged.

## Library, Template, and snapshots

The settings library stores reusable styles. When a theme or border is applied to a Template, the Template also stores a snapshot of the data needed to preserve its appearance.

This has important consequences:

- removing a theme from the library does not erase the copy already stored in a Template;
- removing a border from the library does not disable a frame already saved in a Template;
- importing a style adds it to the library but does not automatically apply it to every Template;
- select the imported style in a Template to use it there.

Token frames and individual block appearance are separate settings and are not part of `.forgestyle`.

## Recommended sharing workflow

1. On the source installation, open **Settings → Style library**.
2. Click **Export style library**, or export one theme/frame from **Appearance**.
3. Send the `.forgestyle` file with a short description of the style.
4. On the destination installation, open **Import .forgestyle**.
5. Review each preview and conflict; use **Keep both** to experiment without replacing the existing library.
6. Open the desired Template and select the newly imported theme or border.
7. Save the Template.
